# 复现课堂

> 帮助教师把别人的优秀教学实践，逐渐变成自己的真实教学实践。

“复现课堂”不是 AI 教案生成器、资源下载站或在线 IDE。它关注教学项目从一位教师传播到另一位教师时最容易丢失的信息：环境、对象、步骤、设计理由、失败经验、适配方法和课堂反馈。

## 核心目标

平台围绕四项能力设计：

- **可复现**：清楚知道要准备什么、按什么步骤做、成功是什么样、失败怎么办。
- **可理解**：看见原作者的关键决策与设计理由，而不只是照教程操作。
- **可迁移**：根据自己的年级、设备、课时和学生条件，得到有理由的修改建议。
- **可验证**：将复现记录与课堂实施反馈沉淀为下一位教师可参考的证据。

## 当前实现

这是一个可直接运行的本地前端原型，使用浏览器 `localStorage` 保存演示数据。

### 已包含的流程

```text
发现项目
  → 判断条件
  → 发起复现
  → 准备清单与步骤进度
  → 记录卡点
  → 提交结果与反思
  → 理解项目
  → 条件适配 / 学科迁移
  → 生成外部 AI 任务包
  → 课堂反馈
  → 项目版本关系与知识证据页
```

### 主要页面

| 页面 | 功能 |
| --- | --- |
| `#/` | 首页、项目类型探索、精选项目复现地图、信息准备度 |
| `#/projects` | 搜索、学科/年级/类型/难度/硬件筛选与排序 |
| `#/projects/[slug]` | 快速判断、复现指南、深入理解、真实反馈 |
| `#/projects/new` | 12 步项目上传向导、草稿与发布 |
| `#/reproductions/[id]` | 复现清单、步骤进度与卡点记录 |
| `#/me/projects` | 我的项目、团队与归档管理 |
| `#/projects/[slug]/learn` | 简单、标准、深入三种理解模式 |
| `#/projects/[slug]/adapt` | 条件适配方案 |
| `#/projects/[slug]/develop-with-ai` | 可复制、下载的外部 AI 协作任务包 |
| `#/projects/[slug]/transfer` | 学科迁移与融合质量检查 |
| `#/projects/[slug]/classroom` | 匿名化课堂实施反馈 |
| `#/projects/[slug]/versions` | 项目改编关系 |
| `#/knowledge` | 实践数据计数与数据不足状态 |

## 快速开始

### 环境

- Python 3
- Node.js 与 npm（仅用于统一运行检查命令）

### 运行

```bash
npm run start
```

然后打开：

```text
http://127.0.0.1:4173
```

也可以直接在浏览器中打开 `index.html`。项目采用 hash 路由，不需要额外服务器路由配置。

### 检查

```bash
npm run build
npm test
```

## 演示数据与隐私

- 内置的六个教学项目均标注为 **示例项目 / Demo**，不代表真实教师案例、真实课堂实施或真实复现成功率。
- “信息准备度”只根据项目字段的完整性计算，不代表复现成功率。
- 演示账户、团队、项目、复现与课堂反馈只保存在当前浏览器的本地数据中。
- 平台禁止上传学生姓名、学号、联系方式、可识别正脸、可识别语音和其他敏感身份信息。
- 演示版不上传文件，也绝不执行用户提供的代码。

## AI 使用原则

当前的 AI 信息检查与任务包均为 **Mock 实现**，不会调用外部模型。

AI 在本平台中只适合用于：

- 提取和整理项目信息；
- 检查复现信息缺失；
- 解释技术概念与报错；
- 生成条件适配建议；
- 整理外部 AI 协作任务包。

任何 AI 输出都必须由教师确认后保存或发布。AI 不能自动发布项目、自动认证项目，或编造课堂与复现数据。

## 真实部署前需要接入的能力

当前原型没有连接真实服务。生产环境建议使用 Next.js + TypeScript + Supabase，并补齐：

- Supabase Auth 与邮件验证；
- PostgreSQL 数据库及 Migration；
- 文件对象存储、格式/大小限制和安全扫描；
- 服务端权限校验与审计；
- 真实的项目、复现与课堂数据；
- 通过环境变量配置的 AI Provider；
- 真实用户可用性测试与教育质量审核。

在获得真实数据前，`#/knowledge` 应持续显示“当前数据不足，暂不能形成可靠结论”。
