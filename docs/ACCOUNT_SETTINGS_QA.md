# 账户页面与密码验收

日期：2026-09-11。范围：管理账户、个人账户页面、密码规则，以及发布后的原有功能回归。

## 本轮改动

- 管理页提供所有账户搜索、明确标注的当前页角色／状态筛选、选中账户编辑及操作记录。创建、资料编辑、密码重置和启停用分别呈现。
- 个人页分为身份资料、修改密码和登录会话；普通成员看不到管理员入口。显示名称由管理员维护。
- 新设密码至少 8 位，可纯数字，UTF-8 总长度不超过 72 字节。创建、重置、自主改密、初始化及本地／云端提供方保持一致。生成初始密码为 8 位随机数字，创建和重置要求二次确认。
- 既有密码保持有效；新建成员直接登录，无强制改密。管理员重置密码后原有的本人改密流程保留。
- 修复账户列表刷新后操作意图变化、旧请求污染新会话、旧停用确认影响新登录身份的问题。用身份代次检查覆盖 A→B→A 场景。
- 主内容容器获得程序焦点时不再出现两侧竖线；真实控件保留键盘焦点提示。

## 验证方法与边界

完整自动化套件覆盖目录、存储、账号、项目、上传、SQL、备份、AI 与物理示例。最终改动另外运行账户回归及浏览器检查。浏览器测试使用隔离的本机 Chrome 临时会话与临时 SQLite，不接管操作者浏览器，也不读取真实密码。

布局矩阵包括管理页／个人页 × 1440／390 像素 × 简体／繁体／英文 × 浅色／深色，共 24 种；检查横向溢出、按钮名称、权限入口、筛选和键盘操作，并保存代表性截图目检。现有账户与项目浏览器脚本另外覆盖实际表单提交、入场、用户隔离、上传发布及完整备份导入。

Supabase 的 8 位纯数字规则使用真实、独立生成的临时 QA 账号验证，覆盖 7 位拒绝、8 位创建、登录、自主改密、管理员重置、旧会话撤销及新账号无强制改密。测试不会修改已有 admin 或 test 的密码；结束时停用本轮 QA 账号并撤销会话。

`supabase/config.toml` 是仓库的 CLI 配置，不意味着已通过管理 API 修改托管 Auth 设置。托管环境的兼容性以真实创建／登录／改密／重置结果为准。

本轮真实 DeepSeek 调用使用 `deepseek-flash`，HTTP 200，输入 1,259 tokens、输出 237 tokens。教学内容质量仍需使用者审阅；字段完整不代表课堂成效验证。

账户浏览器检查曾在并行运行时超过原有 reduced-motion 登录 3 秒计时断言，独立重跑通过，未放宽时限。该项时间包含本机密码验证及浏览器调度，不作为线上响应时间承诺。布局测试显式激活隔离测试页面，避免后台调度干扰。

所有本轮临时云端 QA 均已停用，会话已撤销；项目验收生成的公开版本已撤回。既有 admin、test 密码与两个正式示例未修改。保留生成的私有测试版本及审计记录，未删除原有资料。

私有测试凭据、会话、原始报告和运行日志仅保存在被 Git 忽略的 `.local/`，不进入发布包或仓库。正式站点以上项目采用 HTTP／API 验收；浏览器布局与交互验收针对同一前端文件的隔离本地环境。
