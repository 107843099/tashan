# 当前开发与下一步

本轮是 v3.4：在已有账号入口和个人工作台上，补齐稳定项目编号、版本、完整备份以及服务端保存与发布。Supabase 账号与数据库、私有 R2 流式上传已接通，Cloudflare 已部署并绑定 [tashan.dev](https://tashan.dev)。10 MiB 附件与 5 MiB 封面的边界、正式域名业务和真实 AI 调用已通过验收；持续负载测试及本轮浏览器视觉与手机实机验收尚未完成。实际范围见 [2026-09-11 发布验收](RELEASE_QA_2026-09-11.md)。

## 已有约定继续保留

登录放在原石场景，新账号验证成功后直接转场进入发现页首页顶部；用户可在个人页自主修改密码，管理员重置后的强制改密流程保留。访客可浏览公开目录和体验作品，收藏、创作任务、上传与个人工作台需要登录。旧匿名资料不自动载入游客库，不自动归给第一个登录的人；管理员继续手动发账号，不增加公开注册。

账号创建、重置、停用和角色调整由服务端检查；多标签页、过期会话、退出及账号切换不能让上一人的工作台或预览继续显示。生成初始密码、表单附近的规则提示和创建后定位账号保留。以后如需显示登录前的来源项目，也不直接改变当前首页落点约定。

## v3.4 本轮交付范围

| 对象 | 本轮关系与行为 | 验收重点 |
| --- | --- | --- |
| 项目 | 保留 `project_id`，增加稳定项目编号，服务端关联 `owner_id` | 改标题不换身份；同名项目不误合并 |
| 版本 | 固定 `version_id`、版本序号、内容快照和来源引用 | 旧版本不被新编辑覆盖；同一次上传重试不重复生成版本 |
| 文件 | 内容哈希、类型与大小随版本保存 | 封面和附件完整；同一账号相同内容可复用 |
| 备份 | 项目、文件、草稿、版本、收藏与创作任务；支持导出本人服务端项目的完整版本历史 | 导入先核对重复和冲突；保留旧 ID 对照，不默默覆盖 |
| 服务端保存 | 用户明确上传版本；SQLite 本机模式与 Supabase 云模式分开 | 页面说明保存位置；换浏览器可读取已上传的本人版本 |
| 发布 | 本人明确发布一个已保存版本，支持撤回 | 新草稿不影响公开版本；游客只能读当前公开版本，不能读私有历史 |
| 云账号迁移 | 先生成只读计划，再显式创建核对过的新账号 | 不覆盖云账号；新初始密码可直接登录、个人页自主改密；浏览器资料不自动合并 |

精选项目已有的 `earth`、`poetry` 等 ID 继续保留。来源引用应尽量包含当时项目编号和版本 ID，避免仅用可变化的标题描述出处。恢复本人的服务端版本保留项目及版本身份；把公开作品保存为自己的副本时创建新身份，并保留来源。恢复旧版本作为待编辑内容后，再次保存形成新版本，不抹掉历史。

上传先覆盖单文件 HTML、Prompt、封面与原始附件；ZIP 本轮作为附件保存和下载，不自动解包成可运行网站。上传 HTML 继续隔离预览，下载入口不能让原始 HTML 取得账号站点权限。私有 Storage 桶不发公共对象地址，公开版本也经平台 API 判断当前发布状态。

本轮验收必须区分三个环境：浏览器本地工作台、本机持久服务、真实 Supabase。只有在真实云完成“管理员建号 → 成员直接登录与自主改密 → 上传版本 → 另一浏览器读取 → 发布 → 游客读取 → 撤回 → 跨账号拒绝访问”后，才将云服务状态标为可用。配置与迁移步骤见 [CLOUD_SETUP.md](CLOUD_SETUP.md)。

## 下一步：补齐完整项目包与资料迁移

优先支持带依赖的作品包：明确入口文件，检查相对图片、脚本、字体和动态模块；检查 ZIP 内路径、解压后大小与文件数量，再放入隔离运行环境。缺依赖时列出缺失项，不能用空白预览当作运行成功。单文件和完整包继续提供原件下载。

本地账号迁云的 ID 对照目前只记录身份映射，不自动移动浏览器或本机服务器数据。下一步提供按本人确认的批量迁移预览：显示目标账号、项目数量、重复版本与存储量，上传完成后核对文件哈希；允许重试未完成项，并保留来源记录。收藏、任务与未上传草稿是否跨设备同步单独设计，避免把“项目已上传”误认为整个工作台都已同步。

完善容量和恢复：展示账号剩余空间、版本数量与上传失败原因；设计未完成上传的清理、版本保留、删除与恢复策略。先让删除行为和恢复期限清楚，再批量清理附件，不能仅按文件名猜测哪些文件无用。

## 后续：管理、教学验证与模型任务

账号管理下一步补齐账号到期、恢复与批量发放，明确转交项目和停用后作品可见性的规则。学校或班组分组在实际人数增加后引入；目前不增加复杂组织体系或多人实时编辑。管理员、成员、访客三类权限先保持清楚，项目作者发布自己的版本与未来审核机制分开设计。

教学建议、运行检查与真实课堂验证分开记录。生成海报或网页是备课示例，课堂成效由教师补充实际记录；版本引用和使用许可一起保留，让再创作能回到原作品而不模糊来源。

已接入 DeepSeek 上传必填项自动分析、教学资料建议和创作 Prompt 优化，三条用途均完成真实接口验证。密钥仅由服务端读取，有账号与全站限流、超时、取消、结果审核和用户输入保护，详见 [AI 助手说明](AI_ASSISTANT.md)。后续再把长时间生成任务、历史用量账目、运行沙箱和按版本追踪的成果文件纳入统一任务系统。当前不支持网页/图片生成任务、自动执行模型代码或自动发布；评论、推荐与实时协作放在这些基础流程之后。
