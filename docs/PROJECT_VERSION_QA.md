## 已验证

- `npm test`：目录、存储、界面资料映射、账号 API、本机账号、项目模型/接口和云配置工具自测通过。默认项目接口套件有一项可选 PostgreSQL 测试；另一次指定 `PGLITE_MODULE` 的运行执行了全部 15 项，零失败、零跳过。
- PostgreSQL 实际执行两份 SQL 迁移以及上传预留、文件提交、发布和撤回 RPC。覆盖未完成上传、同版本重试、停用账号、并发发布冲突和匿名权限。此测试使用 PGlite，不是 Hosted Supabase。
- `npm run test:browser`：原石场景登录、错误反馈、首次改密、管理员建号、游客写入限制、账号隔离、三语、手机/横屏、减少动效与 WebGL 回退通过。
- 项目浏览器流程：上传 v1 后保持私有 → 明确发布 → 未登录访客打开固定版 HTML → 编辑并上传 v2，公开内容仍为 v1 → 选择已上传版本（精确版本链接刷新后保留选定版本） → 发布 v2 → 撤回后公共元数据和文件返回 404。
- 新浏览器登录同一账号后，从本机持久服务取回项目，保持项目 ID、编号、版本 ID 与序号；再次上传不重复生成版本。该流程验证“服务端取回”，不代表已连接互联网云端。
- 本人服务端完整历史导出包含两版快照，未变动的附件和封面去重；工作台备份包含收藏与任务；重复导入不新增重复项目。恢复旧版本产生草稿，当前正式版本和历史不被覆盖；异步读取记录保留展开状态。
- 20 MiB 附件与 5 MiB 封面的 v1 导入、v2 往返和哈希校验通过；损坏 Base64、容量超限与事务失败不会部分写入。大附件校验采用线性扫描，避免旧正则栈溢出。
- 多标签页收藏/任务更新在 IndexedDB 事务内合并，导出读取已保存状态；首次旧资料迁移不会覆盖另一标签页已完成的初始化。
- `npm run build`：静态发布包与资源哈希、入口及依赖检查通过，不含账号服务器源码、SQL、数据库、密钥或 `.local/`。

## 环境与边界

2026-09-10 已完成真实 Supabase 配置：服务端密钥保存在 Git 忽略的 `.dev.vars`；6 张业务表和 21 个函数在同一事务中建立，RLS、服务端专用授权、审计序列权限及迁移历史经过数据库实际核验。公开注册和匿名登录关闭，保留密码提供方；私有 `tashan-projects` 桶通过 Storage API 创建，单文件上限 20 MiB。已建立云端 `admin` 并通过真实登录验证，随机强密码仅保存在本机私有文件。数据库连接使用控制台提供的 CA 证书，校验证书链与主机名。

控制台确认组织为 Free：数据库每项目 0.5 GB，文件存储组织共享 1 GB，未缓存/缓存流量各 5 GB，月活用户 50,000；Storage 全局单文件限制固定为 50 MB。查看时数据库用量约 5%，用量有统计延迟。这些是套餐额度，不是平台保证的并发容量。免费套餐不含自动备份，且长期不活跃会暂停，见 [官方套餐说明](https://supabase.com/pricing)。

Worker 上传策略增加 10 项测试，验证无显式配置时暂停上传、Node 原限制不变、前后端限制一致、超限请求在解码或保存前被拒绝。此策略不代替真实 Worker CPU/内存压测。静态发布包另做实际私有密钥和密码值扫描，未发现泄漏。

真实云端接口验收通过 58 项：管理员创建成员、首次改密、重新登录、成员不能管理账号；极小 HTML 与 PNG 的两个版本上传、稳定编号及来源引用一致，文件 SHA-256 读回一致；管理员不能读取成员私有项目；游客仅能读取已公开的 v1，不能读取私有 v2；撤回后公开元数据和文件返回 404。测试经本机 Node API 连接 Hosted Supabase Auth、Postgres 和 Storage，不是模拟提供方。测试账号均已停用、会话已失效、公开内容已撤回，仅保留极小私有验收记录及审计。最终无秘密报告保存在本机 `.local/cloud-qa-report-b6c31cba60.json`，不进入发布包。
