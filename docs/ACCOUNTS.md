# 账号使用与配置

v3.4 保留“管理员发账号 → 用户登录 → 使用个人工作台”的流程，并增加明确保存的项目版本与服务端持久化。没有公开注册入口；账号由管理员创建和管理。普通开发模式使用本机 SQLite，云模式使用 Supabase；浏览器草稿与服务端保存的版本分开管理。本机已配置真实 Supabase，并创建云管理员；其他环境需要自行配置私有变量。验证范围见 [项目验证记录](PROJECT_VERSION_QA.md)。

## 本地开发

需要 Node.js 22.13 或更新版本，以及 Python 3。账号服务使用 Node 内置 SQLite，不要求安装 Supabase 或提供密钥。

```sh
npm run dev:setup
npm run dev
```

`dev:setup` 引导建立第一个管理员。密码在终端隐藏输入，不通过命令行参数、仓库文件或默认密码分发。建立后打开 `http://127.0.0.1:4173/`，使用刚设置的账号登录，再由管理员在账号管理界面创建成员。后续普通启动只需 `npm run dev`。

开发服务仅绑定本机回环地址。`.local/` 存放本地账号数据库、会话、服务端项目版本与附件，不属于发布包，也不通过静态文件接口直接提供。保留该目录可在重启后继续使用本地账号与已上传到本机服务的项目；不要把它上传为网站素材。本地账号与 Supabase 账号是两套独立数据，切换提供方不会自动迁移账号。

`npm start` 与 `npm run dev` 都启动账号开发服务。`npm run preview` 仅预览 `dist/`，不提供账号 API。不要在存有私有配置的项目根目录使用通用静态文件服务器。

## 登录、访客与入场

登录表单直接放在原石场景中。账号密码错误时停留在同一场景；新账号使用管理员分配的密码验证成功后，直接播放碎玉动效进入平台，无需先修改密码。用户可随时在「我的账户 → 修改密码」填写当前密码和新密码，自主更新。管理员重置密码后的保护流程仍保留，在原石场景设置新密码后再转场。登录成功后始终进入发现页首页顶部，不返回之前点击收藏或上传的位置。

“游客模式”关闭登录开场，直接进入公开项目库。游客可以浏览、筛选、查看项目详情和体验原作品；收藏、保存创作任务、上传、备份与个人工作台需要登录，账号管理需要管理员身份。账号服务未连接时仍可选择游客模式浏览。

游客页面只展示公开目录，不加载旧匿名项目与草稿，也不自动将旧资料归入任何账号。恢复已有登录会话不会重复播放开场，登录后的页脚仍可重播手动点石体验。

## 管理员与成员

管理员负责创建账号、调整账号状态和处理密码重置。成员只能操作本人工作台及私有项目，并可明确发布或撤回自己的指定版本；不能创建账号或修改其他人的资料。管理员身份也不会自动取得其他人的私有项目编辑权。管理能力和项目所有权由服务端检查，隐藏按钮只是界面表现。

管理页将账户列表与选中账户的编辑区并排展示，手机上按顺序排列。搜索查询所有账户，角色与状态下拉只筛选当前页，界面会明确标注。修改资料、重置密码和停用账户分别操作；停用前显示确认，账号及其项目资料不会被删除。切换登录身份时，旧请求和未完成的确认不能继续影响新会话。

「我的账户」分为身份资料、修改密码与退出登录三部分。成员可以查看用户名、显示名称和创建时间；显示名称仍由管理员维护。两个页面均支持简体、繁体、英文及深浅色，错误信息显示在相关字段附近。

创建表单在输入区解释用户名与密码规则，错误反馈显示在表单附近；显示名称可使用中文，留空时沿用用户名。“生成初始密码”会同时填入 8 位随机数字和确认密码，可通过眼睛按钮查看。创建接口成功后，列表清除搜索条件、回到第一页并选中新账号，便于继续核对和修改。

建立账号后，页面显示可复制的用户名和初始密码，离开账户管理或收起后清除；这些信息仅在当前页面内存中短暂保留，不写入浏览器存储。管理员通过约定的渠道把用户名和初始密码交给本人。平台不自动发送邮件，也不从公开注册请求创建账号。不要把密码写进项目标题、Prompt、公开示例或教学资料。

会话通过 HttpOnly Cookie 维护，账号 API 不把服务密钥下发给浏览器。退出后继续操作个人资料需要重新登录，公开项目可用游客模式浏览；被禁用的账号不能继续使用受保护接口。用户名为 3–32 位英文字母、数字、下划线或连字符，首位为字母或数字，保存时统一小写。新设密码至少 8 位，允许纯数字，不要求混合字母；UTF-8 编码不超过 72 字节，已有密码继续有效。创建、重置与本人改密均遵守同一规则。管理员新建账号时分配的密码可直接使用，不强制首次登录改密；管理员重置密码后仍要求本人设置新密码。

## 个人项目与旧资料

浏览器保存的项目、草稿、收藏和创作状态按账号隔离，用户选择上传的版本才进入当前服务端。SQLite 模式将这些版本与附件保存在本机；配置 Supabase 后，云模式才会保存到云端。账号命名空间用于避免切换时混入另一人的工作台，不能代替设备层面的账户隔离，也不会把所有本地资料自动同步。

旧匿名资料不会因为新增登录而删除，也不会载入游客项目库。登录后在工作台选择“导出旧版浏览器资料”，再使用备份导入功能放入当前账号，操作后核对项目、草稿与工作台状态。旧存储键不会因为导出或账号迁移被删除。新版备份模型包含项目、文件、草稿、版本、收藏与创作任务；旧版备份没有的内容不能凭空恢复。更换设备、浏览器或站点地址前仍需备份未上传的资料；新增账号或保存一份云端项目不等于全部工作台自动同步。

本机账号迁到云端时需要新初始密码与明确的新旧 ID 对照。先 dry-run，再对核对过的计划显式 apply；不覆盖同名云账号，不直接绑定浏览器私有空间。详细步骤见 [云端配置与账号迁移](CLOUD_SETUP.md)。

个人 JSON 备份不包含密码、账号表或会话。仅存在服务端的本人项目可单独导出完整版本历史；这不会包含未上传草稿和其他工作台项目。账号灾备需另行保存本机 SQLite 与配套文件，或云端数据库和 Storage；具体范围见 [备份与灾难恢复](DEPLOYMENT.md#备份与灾难恢复范围)。

原始互动 HTML 使用响应级沙箱运行，上传 HTML 使用隔离预览。它们可以演示交互，但不应与账号管理接口共享可执行的站点权限。

## 配置线上账号服务

线上适配使用 Supabase Auth 和仓库中的数据库迁移，Cloudflare Worker 调用它们。当前仓库不包含可用的 Supabase 项目凭据；没有配置和执行迁移前，线上账号服务不能启用。

1. 准备 Supabase 项目，在 SQL Editor 中执行 `supabase/migrations/` 下的迁移，按文件名顺序执行。
2. 在 Supabase Authentication 的设置中关闭 **Allow new users to sign up**，同时不要启用匿名注册。只保留管理员发放账号的流程。相关设置见 [Supabase 官方配置文档](https://supabase.com/docs/guides/auth/general-configuration)。
3. 为 Worker 配置 `SUPABASE_URL` 与 `SUPABASE_SECRET_KEY`。密钥只能放在 Workers Secrets 或本地未追踪的配置中；旧项目的 `SUPABASE_SERVICE_ROLE_KEY` 仍兼容，二者只需配置一种。`SUPABASE_AUTH_EMAIL_DOMAIN` 可选，默认 `accounts.tashan.invalid`，只用于用户名在 Auth 中的内部映射，不要求用户填写邮箱。
4. 在受控终端为首次管理员运行引导命令，按提示隐藏输入密码：

```sh
npm run accounts:bootstrap -- --username your-admin --display-name "管理员"
```

先将 Supabase 配置放进当前终端的环境变量，或复制 `.dev.vars.example` 为 `.dev.vars` 后在本机填写。`npm run accounts:bootstrap` 会加载存在的 `.dev.vars`，已有终端环境变量优先；只在 Cloudflare 面板配置 Secret 不会自动传给本机。引导命令不把密钥作为参数，也不输出密码。已初始化的账号环境不能借此反复创建管理员；后续账号使用管理员界面管理。

配置完成后先运行 `npm run cloud:check`。`npm run dev:cloud` 显式选择 Supabase，并在 4173 端口提供本机界面；先停止原 SQLite 服务。普通 `npm run dev` 仍选择 SQLite，填写凭据不会自动切换其数据源。`npm run dev:worker` 则在 4176 验证 Worker 适配。两种云模式都访问真实 Supabase，其中创建、禁用账号和上传项目会修改配置项目的数据。Wrangler 本地私有变量与线上 Secrets 的区别见 [Cloudflare Secrets 文档](https://developers.cloudflare.com/workers/configuration/secrets/)。

## 验证与本轮限制

```sh
npm run test:accounts
npm run test:cloud-tools
npm test
npm run build
```

测试覆盖账号接口、权限和本地提供方；发布检查确保 `.local/`、服务端文件、SQL、私有变量和数据库不进入静态发布目录。真实 Supabase 的配置与端到端验收记录见 [项目验证记录](PROJECT_VERSION_QA.md)；本地测试不能代替云端验证。

平台已通过 Cloudflare 部署到 [tashan.dev](https://tashan.dev)，Supabase 保存账号与项目版本，新上传附件进入私有 R2，旧 Supabase Storage 附件仍可读取。DeepSeek 提供教学建议、Prompt 优化和上传资料分析。多人编辑和 ZIP 解包运行尚未实现。本文描述实现边界，浏览器交互与正式域名验证结果见 [账户页面与密码验收](ACCOUNT_SETTINGS_QA.md)。后续范围见 [下一版本](NEXT_VERSION.md)。
