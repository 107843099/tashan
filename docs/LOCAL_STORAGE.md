# 本地资料、版本与备份

v3.4.0-dev.1 中，`assets/js/storage.js` 提供 `window.PracticeStore`。浏览器工作台包含项目、原始附件、封面、草稿、收藏、创作任务与版本快照；用户明确上传的版本另存到当前服务端。普通开发模式使用本机 SQLite 与私有文件目录；云端账号、版本与权限在 Supabase，新 Worker 上传文件进入私有 R2，旧 Supabase Storage 文件按原索引保留可读。

## 浏览器与账号范围

登录账号使用当前站点来源下的 IndexedDB 数据库 `tashan-practice-library-account-<user-id>`；旧匿名数据库 `tashan-practice-library` 保留。数据库结构版本仍为 `1`，通过 `projects` 和 `meta` 两个对象仓库保存资料；下文 JSON 备份的格式版本 `2` 与 IndexedDB 结构版本不是同一个概念。

更换浏览器，或更换协议、域名、端口，会进入不同的浏览器资料库。同一来源只改入口文件名，不改变资料范围。语言和主题仍是站点偏好；收藏和创作任务现在保存在账号的 IndexedDB 工作台状态中。账号首次读取尚未初始化的工作台时，从该账号原 localStorage 键迁入；不会用旧值覆盖已初始化的工作台，也不删除原存储键。

游客仅浏览公开内容，不加载旧匿名项目、草稿、收藏或任务。登录后才可在工作台选择“导出旧版浏览器资料”；前端将旧匿名收藏、任务作为 `workspace` 参数交给 `exportGuest()`，与原匿名数据库资料合并导出，不切换或写入当前账号空间。旧项目缺少稳定编号时会补齐编号，原 ID 和教学内容保留。导出后仍需本人明确导入目标账号，不自动认领或上传。

账号切换会中止旧事务、撤销 Blob URL 并清空缓存。已打开的私有预览在会话变化或重新可见时重新核对身份，等待期间清空内容并禁用下载。账号命名空间用于避免界面混入其他人的资料，不是设备上的加密隔离，也不能代替服务端所有权检查。

## 项目、编号与版本

`list()`、`get(id)` 读取项目，`put(record)` 新建或更新，无 ID 时生成 `local-…`。每个本地项目有独立且稳定的 `projectCode`，格式为 `TS-L-` 加 16 位大写十六进制字符；修改标题、文件名或说明不会改变 ID 和编号。旧项目首次读取时补编号，精选目录既有的 `earth`、`poetry` 等 ID 继续保留。

`getDraft()`、`putDraft()` 和 `clearDraft()` 管理一份独立草稿。`put(record, {clearDraft:true, saveVersion:true})` 在同一事务中完成保存项目、生成版本和清除草稿；写入失败时保留原项目与草稿。普通 `put()` 不会自行创建版本，页面完成保存时显式选择生成版本。

`saveVersion(id, {note})` 保存不可变快照，产生 `version-…` ID、递增序号、时间和说明。`listVersions()`、`getVersion()` 读取历史；`restoreVersion()` 将旧版内容恢复为可编辑草稿，再次完成保存才生成新版本，不改写原历史。来源引用保存项目 ID、项目编号及可获得的来源版本信息。

从服务端恢复本人的版本使用 `adoptVersion()`，保留原项目、编号及版本 ID；若本地存在不同内容，不会直接覆盖。公开作品保存为本人副本时分配新身份，并保留来源引用。删除浏览器项目只清除本地记录、相关版本及收藏，不删除服务端版本，也不会自动撤回公开作品。

## 文件和容量

项目元数据允许普通对象、数组、文字、有限数字、布尔及 `null`，拒绝函数、循环引用和不可移植对象。浏览器的单项目文字资料上限为 1 MiB；当前 Worker 云上传另限版本文字 64 KiB、清单 96 KiB，页面从服务端 capabilities 读取实际限制，超过云限制仍可保存在浏览器。附件使用以下字段保存 Blob：

```js
{
  title: { 'zh-CN': '圆的探索', en: 'Exploring circles' },
  attachment: { name: 'project.html', type: 'text/html', blob: file },
  coverFile: { name: 'cover.png', type: 'image/png', blob: imageFile }
}
```

| 范围 | 当前限制 |
| --- | --- |
| 单个附件 / 封面 | 10 MiB / 5 MiB |
| 浏览器账号资料库 | 100 个项目、1000 个版本快照、总量 50 MiB |
| 收藏与创作任务 | 合计 5 MiB，计入浏览器总量 |
| 便携 JSON 导入文件 | 编码后不超过 70 MiB；解码后的资料仍受 50 MiB 限制 |
| 当前服务端账号 | 100 个项目、每项目 100 个版本、账号资料合计 200 MiB |
| 当前 Worker 云上传清单 / 版本文字 | 96 KiB / 64 KiB；附件和封面不含在清单正文中 |

界面中的 MB 按 `1024 × 1024` 字节计算。50 MiB 包括项目、草稿、版本文字资料及工作台状态；附件按内容 SHA-256 去重计入容量，便携备份也只保存一份相同内容。这个计算不承诺浏览器底层数据库占用恰好等于该数值，实际可用空间还受浏览器配额限制。服务端 200 MiB 是另一项配额，不会把单份便携备份上限提高到 200 MiB。

附件扩展名支持 HTML、HTM、ZIP、MD、Markdown、TXT、JSON、PDF、DOCX、PPTX、PNG、JPG/JPEG、WebP、GIF；封面支持 PNG、JPEG、WebP、GIF。空 MIME 可按扩展名补全。校验错误拒绝整个操作；浏览器空间不足时保留 `QuotaExceededError` 名称供页面提示。

Worker 的 `r2-stream-v1` 流程先准备 pending 版本，再传原始文件流，所有文件核对成功后才完成版本。数据库记录每个版本的存储后端与已验证对象回执，重复上传不覆盖旧对象或改写历史；中断时重试同一版本。浏览器不直接访问公开桶，预览、下载、恢复与完整历史导出仍经过同一个授权项目 API。R2 文件不自动搬到旧 Supabase 桶，旧文件也不自动迁入 R2。

`npm run dev:cloud` 的 Node 服务仍使用旧 JSON / Supabase Storage 上传流程，当前没有 R2 binding，读取 R2 文件会返回明确的 503。需要在已配置 R2 binding 的 Worker 站点读取或导出这类版本；本地 Worker 的模拟桶与线上私有桶也不共享文件。这个环境差异不表示云文件丢失。

## 完整浏览器备份与导入

`exportAll()` 返回当前账号的 JSON Blob；页面会先尝试保存编辑中的草稿。`exportGuest({workspace})` 导出旧匿名资料与显式提供的旧工作台状态。新格式为：

```js
{
  format: 'tashan-practice-library',
  version: 2,
  exportedAt: 'ISO timestamp',
  projects: [],
  draft: null,
  workspace: { bookmarks: [], tasks: {} },
  versions: [],
  files: { /* SHA-256: { bytes, base64 } */ }
}
```

项目、草稿和版本中的文件描述保存 `name`、`type`、`sha256`，实际内容放在共享 `files` 表。同一附件跨项目或版本使用时不重复编码。备份不包含密码、账号表、Cookie、会话、服务密钥或其他账号资料。

`inspectBackup(file)` 在导入前检查结构、哈希、容量、项目与版本对应关系，并返回新增、相同、冲突项目与任务的摘要。`importBackup(file, {conflict:'skip'|'copy'})` 默认跳过冲突，也可把冲突项目另存副本；不会直接覆盖已有不同内容。相同项目只补齐缺失历史，导入较旧历史不会把当前版本指针倒退。另存副本时同步映射导入数据里的项目、编号、版本与来源引用，原有项目图不改写。

收藏合并去重；冲突创作任务保留当前内容并在结果中报告。已有草稿保留，当前没有草稿才恢复备份草稿。导入计划形成后如有另一标签页更新资料，版本修订检查会拒绝提交，要求重新核对。最终项目、版本、草稿和工作台状态在一个事务中写入，结构错误、附件损坏、超量或写入失败均整体回滚。

仍接受旧格式 `version:1` 的项目与草稿备份，文件可从原内嵌 base64 读取；旧备份未包含收藏、任务或版本时不会虚构这些资料。旧格式导入会补齐稳定编号，新导出统一采用格式 `2`。

## 仅存在服务端的项目历史

普通“导出本地备份”只包含当前浏览器已有资料，不会悄悄下载账号的全部服务端项目。打开本人服务端项目后，可选择“备份此项目全部版本”：页面读取该项目的全部已上传版本及其附件，交给 `exportProjectVersions()` 生成独立、可导入的格式 `2` 备份，无需先把完整历史写入当前 IndexedDB。

该备份包含选定项目的版本、源文件、封面和来源引用；不包含其他项目、未上传草稿、收藏或任务。文件内容去重后加上版本资料仍需在 50 MiB 内，超出时明确拒绝生成，不输出缺少附件或无法导入的“完整备份”。服务端账号可保存到 200 MiB，并不意味着每个历史集合都能打进一个 50 MiB 文件；目前没有自动拆分导出功能。

本机服务中的账号和项目需要同时备份 `.local/accounts.sqlite` 及 `.local/project-files/`。云端灾备需要 Supabase 数据库、`tashan-projects` 旧对象和 R2 `tashan-project-files` 新对象，三部分及其对应关系须一起保留。个人项目历史导出通过同一 API 读取两种存储，但不包含账号表、密码或全站资料，不能代替全站灾备。范围见 [部署文档](DEPLOYMENT.md#备份与灾难恢复范围)。

## HTML 预览

`project-preview.html?project=local-ID` 读取已核对身份的浏览器附件；服务端版本使用 `remote` 与 `version` 参数，公开版本额外标识 `public=1`。服务端仍负责核对私有所有权或当前发布状态，URL 参数不授予访问权限。

自包含 HTML 只进入 `sandbox="allow-scripts"` 的 iframe，未授予同源、弹窗、下载、表单或顶层导航能力。注入的 CSP 允许行内脚本、样式与内嵌图片等，禁止联网请求、外部脚本、对象和嵌套框架。上传代码不能读取平台 DOM 或账号资料库；原始文件下载由外层页面提供。多文件作品和 ZIP 先下载完整附件按说明运行，预览器不自动解包执行。

## 验证与当前边界

使用 Node.js 22.13 或更新版本运行 `npm test`。存储模型检查覆盖去重备份往返、编号与引用、历史补齐、冲突副本、草稿/任务保留、账号切换、哈希损坏和事务失败回滚；项目 API 检查服务端版本、所有权与发布边界。模拟存储测试不能代替浏览器 IndexedDB 和真实云环境验收，相关结果由 QA 文档单独维护。

每个新环境仍需独立配置和端到端验证；新 R2 上传流程的真实 Worker CPU 和正式域名验收另行记录，不由本地测试推定。登录不会自动同步所有浏览器资料；账号迁移也不会自动合并旧私有空间。配置步骤见 [云端配置](CLOUD_SETUP.md)，后续功能见 [下一版本](NEXT_VERSION.md)。
